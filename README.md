# mcp-russia

**Русскоязычная адаптация MCP-репозитория для работы с государственными и публичными данными**

## Статус

Репозиторий переведён на российские и русскоязычные реалии.

Python-пакет `mcp_russia` является единой точкой входа. Историческое имя `mcp_brasil` полностью устранено из кодовой базы, импортов, конфигурации и переменных окружения. Оставшиеся ссылки на бразильский контекст встречаются только в deprecated legacy-модулях данных и документации.

Корневая документация и метаданные переведены в русскоязычный контекст. Полная замена интеграций, доменных моделей и тестов на российские источники данных требует отдельной поэтапной миграции.

## Что уже сделано

- Python-пакет полностью перенесён в `mcp_russia` (исторический `mcp_brasil` устранён).
- Переменные окружения унифицированы: `MCP_RUSSIA_*` (fallback на `MCP_BRASIL_*` удалён).
- Корневой сервер автообнаруживает features из `mcp_russia.data` и `mcp_russia.agenty`.
- Мета-инструменты сервера на русском: `spisok_funktsiy`, `rekomendovat_instrumenty`, `splanirovat_zapros`, `vypolnit_paket`.
- Базовый класс исключений: `McpRussiaError` (устаревший `McpBrasilError` удалён).
- 19 российских модулей данных, переведённых на русские имена переменных и функций.
- 5 модулей с реальными API-интеграциями: ЦБ РФ (cbr-xml-daily.ru), Росгидромет (open-meteo.com), ФНС (egrul.nalog.ru), Госдума (api.duma.gov.ru), Закупки (zakupki.gov.ru).

## Что здесь есть

- Архитектура MCP-сервера на Python с auto-registry для features.
- Рабочие интеграции с реальными API: курсы валют ЦБ РФ, погода и качество воздуха (Open-Meteo), ЕГРЮЛ/ЕГРИП (egrul.nalog.ru), депутаты и законопроекты Госдумы (api.duma.gov.ru), закупки и контракты (zakupki.gov.ru).
- Набор готовых модулей, клиентских обвязок, схем и тестов, которые можно использовать как основу для переноса на российские API.
- Инструменты разработки: `uv`, `pytest`, `ruff`, `mypy`, `Makefile`.

## Текущее направление адаптации

- заменить бразильские источники данных на российские государственные и общественно значимые API;
- подключить реальные API в российских модулях (5 из 19 подключены: ЦБ РФ, Росгидромет, ФНС, Госдума, Закупки);
- дочистить документацию и changelog от исторических бразильских формулировок;
- обновить примеры, тесты и справочные материалы под российские сценарии использования.

## Быстрый старт для разработки

```bash
git clone git@github.com:denis-gordeev/mcp-russia.git
cd mcp-russia
make dev
```

Локальные команды:

```bash
make test             # Запустить все тесты
make test-feature F=ibge
make lint
make types
make ci
make run
make serve
make inspect
```

Часть документации и legacy-модулей ещё содержит бразильский контекст, но рабочая точка входа для запуска и разработки — `mcp_russia`.

## Архитектура

Проект использует подход package-by-feature:

```text
src/mcp_russia/
├── server.py
├── settings.py
├── exceptions.py
├── _shared/
├── data/
└── agenty/
```

Каждая feature инкапсулирует:

- `client.py` для HTTP-интеграции;
- `tools.py` для MCP tools;
- `schemas.py` для моделей;
- `resources.py` и `prompts.py` при необходимости;
- `server.py` с `FastMCP`-регистрацией.

## Документация

Актуализируйте существующую документацию с учётом фактической структуры `src/mcp_russia/`. Часть файлов в `docs/` и `CHANGELOG.md` содержит исторические бразильские формулировки и требует отдельного прохода.

## Разработка и вклад

1. Работайте в небольших, изолированных изменениях.
2. Если меняете поведение кода, запускайте релевантные проверки.
3. Если переводите существующую feature на российский контекст, обновляйте одновременно код, тесты и документацию.
4. Для внешних изменений используйте pull request.

В репозитории отключены GitHub Issues, поэтому для предложений и исправлений ориентируйтесь на pull request и сопроводительное описание изменений.

## Дисклеймер

Проект находится в стадии содержательной миграции. В репозитории могут одновременно встречаться русскоязычные формулировки, российское позиционирование и исторические компоненты исходного бразильского проекта.

На текущем этапе сервер не следует воспринимать как завершенный каталог российских государственных API. Это рабочая кодовая база для поэтапной адаптации под российские и русскоязычные сценарии.

Сервер не должен создавать видимость официального государственного источника. При подключении новых интеграций необходимо явно указывать происхождение данных, ограничения покрытия и условия использования каждого внешнего API.
