# mcp-russia

**Русскоязычная адаптация MCP-репозитория для работы с государственными и публичными данными**

</div>

## Статус

Репозиторий переводится на российские и русскоязычные реалии.

Сейчас в кодовой базе все еще сохраняются исторические имена пакета и модулей, унаследованные от исходного проекта: `mcp-brasil`, `mcp_brasil` и связанные внутренние структуры. Это технический переходный слой, а не целевое позиционирование репозитория.

Корневая документация и метаданные уже приведены к русскоязычному контексту. Полная замена интеграций, доменных моделей и тестов на российские источники данных требует отдельной поэтапной миграции.

## Что здесь есть

- Архитектура MCP-сервера на Python с auto-registry для features.
- Набор готовых модулей, клиентских обвязок, схем и тестов, которые можно использовать как основу для переноса на российские API.
- Инструменты разработки: `uv`, `pytest`, `ruff`, `mypy`, `Makefile`.

## Текущее направление адаптации

- заменить бразильские источники данных на российские государственные и общественно значимые API;
- привести тексты tools/resources/prompts к русскоязычному интерфейсу;
- переименовать пакет, переменные окружения и документацию без поломки совместимости;
- обновить примеры, тесты и справочные материалы под российские сценарии использования.

## Быстрый старт для разработки

```bash
git clone git@github.com:denis-gordeev/mcp-russia.git
cd mcp-russia
make dev
```

Локальные команды:

```bash
make test             # Запустить все тесты
make test-feature F=ibge
make lint
make types
make ci
make run
make serve
make inspect
```

Пока миграция не завершена, часть команд и импортов по-прежнему использует историческое имя модуля `mcp_brasil`.

## Архитектура

Проект использует подход package-by-feature:

```text
src/mcp_brasil/
├── server.py
├── _shared/
├── data/
└── agentes/
```

Каждая feature инкапсулирует:

- `client.py` для HTTP-интеграции;
- `tools.py` для MCP tools;
- `schemas.py` для моделей;
- `resources.py` и `prompts.py` при необходимости;
- `server.py` с `FastMCP`-регистрацией.

## Документация

Актуализируйте существующую документацию с учетом переходного состояния проекта. Значительная часть файлов в `docs/` все еще описывает исходные бразильские интеграции и требует миграции.

## Разработка и вклад

1. Работайте в небольших, изолированных изменениях.
2. Если меняете поведение кода, запускайте релевантные проверки.
3. Если переводите существующую feature на российский контекст, обновляйте одновременно код, тесты и документацию.
4. Для внешних изменений используйте pull request.

В репозитории отключены GitHub Issues, поэтому для предложений и исправлений ориентируйтесь на pull request и сопроводительное описание изменений.

## Дисклеймер

Проект находится в стадии содержательной миграции. В репозитории могут одновременно встречаться русскоязычные формулировки, российское позиционирование и исторические компоненты исходного бразильского проекта.

На текущем этапе сервер не следует воспринимать как завершенный каталог российских государственных API. Это рабочая кодовая база для поэтапной адаптации под российские и русскоязычные сценарии.

Сервер не должен создавать видимость официального государственного источника. При подключении новых интеграций необходимо явно указывать происхождение данных, ограничения покрытия и условия использования каждого внешнего API.
