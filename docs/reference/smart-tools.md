# Умные инструменты

Корневой сервер публикует 4 мета-инструмента, которые помогают находить нужные интеграции, строить план запроса и выполнять несколько вызовов за один проход.

## `spisok_funktsiy`

Показывает все активные модули и статус авторизации.

```text
→ spisok_funktsiy()
← 27 модулей:
   cbrf (6 инструментов) ✓
   rosstat (13 инструментов) ✓
   gosduma (7 инструментов) ✓
   ...
```

Это хороший первый шаг, когда модели нужно понять, какие API вообще доступны в текущем экземпляре сервера.

## `rekomendovat_instrumenty`

Принимает вопрос на естественном языке и предлагает 3-5 наиболее релевантных инструментов.

```text
→ rekomendovat_instrumenty("Какие данные по инфляции и ключевой ставке доступны?")
← Рекомендация:
   1. cbrf_tekushchie_kursy
   2. rosstat_inflyatsiya
   3. cbrf_sravnit_valyuty
```

Как работает:

1. `postroit_katalog()` собирает markdown-каталог всех инструментов
2. Каталог и пользовательский вопрос отправляются в LLM
3. Модель возвращает краткий список инструментов с объяснением и примером использования

**Требует:** `ANTHROPIC_API_KEY`

## `splanirovat_zapros`

Строит структурированный план выполнения для запросов, где нужно несколько API, зависимые шаги или параллельные вызовы.

```text
→ splanirovat_zapros("Сравни расходы на здравоохранение в двух регионах за 3 года")
← План:
   Этап 1: получить данные по первому региону
   Этап 2: получить данные по второму региону
   Этап 3: добавить население и рассчитать на душу населения
```

Модель данных:

```python
class EtapPlana(BaseModel):
    etap: int
    opisanie: str
    imya_instrumenta: str
    parametry: dict[str, str]
    zavisit_ot: list[int]
    obosnovanie: str

class PlanZaprosa(BaseModel):
    zapros: str
    slozhnost: str
    svodka: str
    etapy: list[EtapPlana]
    primechaniya: str
```

Типичные стратегии:

- `obogashchenie`: добавить контекст из другого модуля
- `sravnenie`: сопоставить одну и ту же метрику по разным регионам или источникам
- `kontekstualizatsiya`: подтянуть справочные, демографические или макроэкономические данные
- `параллельно`: выполнить независимые шаги одновременно

**Требует:** `ANTHROPIC_API_KEY`

## `vypolnit_paket`

Выполняет до 10 вызовов инструментов за одну MCP-команду и снижает число обменов между моделью и сервером.

```text
→ vypolnit_paket([
    {"imya_instrumenta": "cbrf_tekushchie_kursy", "argumenty": {}},
    {"imya_instrumenta": "rosstat_spisok_regionov", "argumenty": {}},
    {"imya_instrumenta": "gosduma_spisok_deputatov", "argumenty": {}}
  ])
← [результат1, результат2, результат3]
```

Как работает:

1. `postroit_dispetcherizatsiyu(reestr)` строит отображение `имя инструмента -> асинхронная функция`
2. `asyncio.gather()` выполняет вызовы параллельно
3. Результаты возвращаются в исходном порядке

**Лимит:** максимум 10 вызовов за одну команду

## Когда использовать

| Ситуация | Инструмент |
|----------|------|
| Нужно понять, что вообще доступно | `spisok_funktsiy` |
| Нужно быстро подобрать инструмент под вопрос | `rekomendovat_instrumenty` |
| Нужно разложить сложный запрос на этапы | `splanirovat_zapros` |
| Нужно получить несколько независимых ответов за один проход | `vypolnit_paket` |

## Рекомендуемый поток

```text
1. splanirovat_zapros("сложный вопрос")
2. vypolnit_paket([...независимые этапы...])
3. vypolnit_paket([...зависимые этапы...])
4. модель синтезирует итоговый ответ
```

## Поиск инструментов (BM25)

Полный каталог слишком большой, чтобы всегда публиковать его целиком в LLM-контекст. Поэтому по умолчанию используется BM25-фильтрация:

- анализируется текущий диалог
- инструменты ранжируются по релевантности
- в контекст попадают только N наиболее релевантных совпадений
- мета-инструменты всегда остаются видимыми

Настройка управляется через `MCP_RUSSIA_TOOL_SEARCH`:

| Значение | Поведение |
|----------|-----------|
| `bm25` | Показать только релевантные инструменты |
| `none` | Показать весь каталог |
| `rezhim_koda` | Экспериментальное программное обнаружение |
